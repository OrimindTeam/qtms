# نظرة عامة على نموذج البيانات — QTMS

| البند | القيمة |
|---|---|
| **الإلزامية** | **M** |
| **الطبيعة** | **STATIC** |
| **المالك** | ARCH |
| **التقنية** | **قاعدة بيانات مستندية سحابية (Cloud Firestore)** — حصراً (`ADR-0001`) |

---

## 1. الطبيعة والقيود المترتبة

| الخاصية | الأثر التصميمي |
|---|---|
| **مستندية لا علائقية** | **لا قيود مفتاح أجنبي · لا استعلامات ربط · لا `JOIN`** ⟵ السلامة المرجعية **مسؤولية التصميم والعمليات السحابية** |
| **الاستعلام محدود** | **كل استعلام يحتاج فهرساً مركّباً مُعلَناً** (`indexing-strategy.md`) |
| **التكلفة بعدد القراءات والكتابات** | **قيد تصميمي لا ملاحظة** — يفرض الملخصات الجاهزة (`ADR-0008`) |
| **معاملات ذرّية بإعادة محاولة تلقائية** | تعطي عملياً **نفس ضمان القفل** بلا كلفته |
| **قواعد حماية داخل بنية القاعدة** | **طبقة التفويض الوحيدة** (`ADR-0002`) |

## 2. مبادئ التصميم السبعة

| المبدأ | التطبيق |
|---|---|
| **الفصل بالمصدر في المفتاح** | كل مستند تشغيلي يحمل `sourceId` صراحةً، **وكل رصيد مفتاحه يبدأ بالمصدر** — فيستحيل خلط مصدر بآخر |
| **الفصل بتاريخ المخزون** | كل رصيد وكل حركة صادرة تحمل **`stockDate`** — وهو ما يجعل تصريف متبقي الأيام السابقة ممكناً ومضبوطاً |
| **التكرار المقصود للأسماء** | يُخزَّن اسم النوع والمقوت والرعوي والمصدر **داخل سطور المستند نفسه** — فلا قراءة إضافية للعرض، **ولا يتغيّر المعروض تاريخياً لو تغيّر الاسم لاحقاً** |
| **السطور داخل المستند** | سطور كل مستند تُخزَّن **بداخله**، فيصير حفظه **عملية كتابة واحدة لا تتجزأ** |
| **الأرصدة سجلات مستقلة** | كل رصيد (نوع × مصدر × تاريخ) سجل مستقل — **ليمكن التعامل معه ذرّياً دون تعارض** بين المستخدمين |
| **الدفاتر لا تُحذف وتُعدَّل بضوابط** | التعديل مباشر بصلاحية وسبب وتسجيل إجباري · **والحذف مرفوض نهائياً** (`A-14`) |
| **سجل التدقيق للإضافة فقط** | **الاستثناء المطلق الوحيد** — لا يُعدَّل ولا يُحذف من أحد بمن فيهم المالك |

> **مبدأ ثامن حاكم:** **وحدة القياس جزء من هوية النوع** — كل كمية تحمل
> وحدتها، **ولا تُجمع كميات مختلفة الوحدات أبداً**.

## 3. لماذا الضمار ليس مجموعة مستقلة

> **الضمار هو مستند التوزيع نفسه** مضافاً إليه حقول التسوية — لأن لكل
> **(مقوت × مصدر × تاريخ مخزون)** توزيعة واحدة فقط (`A-09`).
>
> **والمعرّف المركّب `{dealerId}_{sourceId}_{stockDate}` هو ما يفرض هذه
> القاعدة بنيوياً** — فلا تعتمد على فحص تطبيقي قد يُنسى، ومحاولة إنشاء ثانٍ
> **تفشل في القاعدة نفسها**.

## 4. خريطة المجموعات

```text
■ سجلات التهيئة
   sources · suppliers · dealers · items · users · roles · app_settings

■ سجلات حراسة التفرد   (سجلات فارغة معرّفها هو القيمة المُطبَّعة نفسها)
   unique_item_names · unique_supplier_phones · unique_dealer_phones · unique_source_names

■ العدّادات             (تُدار في السحابة حصراً · القراءة مرفوضة للجميع)
   document_counters · daily_sack_counters

■ المستندات التشغيلية
   incoming_count · sacks · daily_prices · distributions
   cash_sales · receipts · discounts · outflows · stocktakes · disposals

■ ★ الدفاتر الأربعة ★
   inventory_ledger · dealer_ledger · supplier_ledger · outflow_ledger

■ الأرصدة والملخصات    (تبنيها السحابة — والكتابة من التطبيق مرفوضة)
   item_daily_balances · dealer_balances · dealer_surplus
   supplier_balances · daily_summaries · pending_entries · aged_remainders

■ الرقابة
   document_amendments · audit_log
```

## 5. الدفاتر الأربعة — مصدر الحقيقة

| الدفتر | يحكم | القاعدة |
|---|---|---|
| **`inventory_ledger`** | رصيد كل نوع | **`GR-01`** — لا يتغيّر رصيد مخزون إلا بسطر فيه |
| **`dealer_ledger`** | رصيد كل مقوت **في كل مصدر** | **`GR-02`** |
| **`supplier_ledger`** | صافي كل رعوي **في كل مصدر** | **`GR-03`** |
| **`outflow_ledger`** | السحبيات والخرجيات **بالمصدر** | **`GR-04`** |

> **ولا توجد أي واجهة تُعدِّل رقم رصيد مباشرة** (`BR-M8-03`).

## 6. حدود الكتابة

| المجموعة | من يكتب |
|---|---|
| **الأرصدة والملخصات** | **السحابة أو المعاملة فقط** — والكتابة من التطبيق **مرفوضة** |
| **`audit_log`** | **السحابة حصراً** · **والتعديل والحذف مرفوضان لأحد** |
| **`document_amendments`** | ★★ **إنشاء بسببٍ اختياري** (`ADR-0020`) · **والتعديل والحذف مرفوضان دائماً** |
| **العدّادات** | **السحابة فقط** — **والقراءة مرفوضة للجميع** |
| **`pending_entries` · `aged_remainders`** | **السحابة فقط** |
| **المستخدمون والأدوار** | **عملية سحابية فقط** — لا كتابة مباشرة |
| **النوع الافتراضي «السكرب»** | **السحابة فقط** · **والتعديل والحذف مرفوضان** |
| **`app_settings`** | **المالك حصراً · مرة واحدة** · **والتعديل والحذف مرفوضان للجميع** |

## 7. العمليات الآلية الإلزامية في السحابة

| العملية | متى | ماذا تفعل |
|---|---|---|
| **ترقيم المستندات** | إنشاء أي مستند | رقم متسلسل فريد — يمنع التكرار بين متزامنَين |
| **الترقيم اليومي للجواني** | إنشاء جونية | الرقم التالي **لكل مصدر × كل يوم** — يبدأ من ١ كل يوم |
| **كتابة سجل التدقيق** | أي إنشاء/تعديل/إلغاء | **إجبارياً بعيداً عن الجهاز** — **ولا ينجح تعديل بلا قيد مقابل** |
| **مزامنة الصلاحيات ونطاق المصادر** | تغيير صلاحيات مستخدم | نسخها إلى رمز الدخول فوراً |
| **إنشاء الحسابات عند إضافة مصدر** | إضافة مصدر | حساب لكل مقوت ورعوي **+ نوع السكرب** |
| **إنشاء الحسابات عند إضافة مقوت/رعوي** | الإضافة | حساب له في **كل** المصادر |
| **إعادة احتساب أرصدة المخزون** | بعد أي حركة أو **تعديلها** | إعادة بناء رصيد (المصدر × النوع × تاريخ المخزون) **من الدفتر** |
| **إعادة احتساب أرصدة المقاوته والضمارات** | بعد أي قيد أو تعديله | الرصيد وقيمة الضمار والمسدَّد والمخصوم والمتبقي وحالة التسوية |
| **تطبيق الفائض تلقائياً** | **إنشاء ضمار جديد** لمقوت له فائض | تسدد وتكتب **البيان الآلي** بتاريخ الدفع |
| **إعادة احتساب سعر الجونية وصافي الرعوي** | أي تغيير يمسّ أنواعها | ⚠️ **بتجميع** — راجع `RISK-03` |
| **بناء المركز المعلّق** | حفظ/تحديث مستند فيه قيمة لاحقة | إنشاء البنود وحذفها فور اكتمالها |
| **بناء المتبقي المتأخر** | بعد كل حركة صادرة · ودورياً | رصد ما لم يُصرَّف وحذفه عند تصريفه |
| **بناء ملخصات ضمار المالك** | بعد كل عملية · وفي نهاية اليوم | ملخص كل مصدر وملخص «الكل» |
| **إعادة بناء يوم سابق بأثر رجعي** | تصريف متأخر أو جرد يوم سابق | + **وسم «⟳ مُحدَّث بأثر رجعي»** وتاريخه |
| **تعطيل الوصول فوراً** | إيقاف مستخدم | إبطال جلسته ورمز دخوله |

> **عقد ملزم لكل عملية إعادة احتساب:** **قابلة للتكرار بلا أثر جانبي** —
> تُعيد البناء **من الدفتر بالكامل ولا تُراكِم** (`PAT-08`).
