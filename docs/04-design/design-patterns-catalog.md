# كتالوج أنماط التصميم المعتمدة — QTMS

| البند | القيمة |
|---|---|
| **الإلزامية** | **O** (اختياري) — أُنشئ لأن النظام كثيف قواعد ويحتاج تسمية موحّدة لأنماطه |
| **الطبيعة** | **LIVING** — يُضاف إليه نمط معتمد جديد بقرار |
| **المالك** | ARCH |

> **قاعدة الاستخدام:** **النمط يُستخدَم لأنه يحلّ مشكلة قائمة، لا لأنه
> موجود في الكتالوج.** والإفراط في التجريد **دَين تقني** لا جودة.

---

## 1. أنماط بنيوية

### `PAT-01` — المستودع (Repository)
| البند | التفصيل |
|---|---|
| **متى** | كل وصول لقاعدة البيانات |
| **لماذا هنا** | **يعزل طبقة النطاق عن حزم المنصة** فتصير المعادلات قابلة للاختبار بلا سحابة — شرط عملي لتغطية ≥80٪ |
| **القاعدة** | **الواجهة تُعرَّف في النطاق، وتُنفَّذ في البنية التحتية** — ولا يعرف النطاق شيئاً عن شكل المستند |
| **مثال** | `SackRepository` ⟵ `FirestoreSackRepository` |

### `PAT-02` — حالة الاستخدام (Use Case)
| البند | التفصيل |
|---|---|
| **متى** | كل عملية يبدأها المستخدم |
| **لماذا هنا** | نقطة واحدة لتنسيق: التحقق → فتح المعاملة → الكتابات → إطلاق ما بعدها |
| **القاعدة** | **صنف واحد لكل عملية**، باسم `فعل + مفعول`، **بلا معادلات بداخله** |
| **مثال** | `ApproveDistribution` · `ClearAgedRemainder` |

### `PAT-03` — كائن القيمة (Value Object)
| البند | التفصيل |
|---|---|
| **متى** | **كل مبلغ وكل كمية وكل تاريخ في النظام** |
| **لماذا هنا** | **أهم نمط في هذا المشروع:** يجعل خلط الوحدات وخلط التاريخين **خطأ ترجمة لا خطأ تشغيل** |
| **القاعدة** | `Money` · `Quantity(value, unit)` · `StockDate` · `EntryDate` — **ولا توجد دالة تجمع كميتين مختلفتي الوحدة أصلاً** |
| **يمنع** | `GR-19` · `RISK-07` — **بنيوياً لا بالتحقق** |

### `PAT-04` — المعرّف المركّب كقيد تفرد
| البند | التفصيل |
|---|---|
| **متى** | الضمار · رصيد النوع في يوم · سعر اليوم · ملخص اليوم |
| **لماذا هنا** | **يفرض `GR-18` («توزيعة واحدة لكل مقوت × مصدر × يوم») في البنية نفسها** — فلا يعتمد على فحص تطبيقي قد يُنسى |
| **القاعدة** | ترتيب الأجزاء **ثابت** (`naming-conventions.md` §4) |

## 2. أنماط سلوكية

### `PAT-05` — دفتر الحركات (Ledger / Event-Sourced Balance)
| البند | التفصيل |
|---|---|
| **متى** | **الدفاتر الأربعة كلها** |
| **لماذا هنا** | **الرصيد = مجموع الحركات دائماً** — فلا حقل رصيد يُحدَّث ويُنسى (`P-01`) |
| **الفرق عن المصدرية الحدثية الكلاسيكية** | **الحركة هنا قابلة للتعديل في مكانها** (`ADR-0004`) — والتاريخ محفوظ في سجل التدقيق لا في سلسلة أحداث غير قابلة للتغيير |

### `PAT-06` — لقطة القيمة (Snapshot / Freezing)
| البند | التفصيل |
|---|---|
| **متى** | **السعر** لحظة الاعتماد · **وزن الحبة** داخل سطر الجونية · **أسماء** الكيانات داخل السطور |
| **لماذا هنا** | **تعديل سعر اليوم أو اسم الرعوي لاحقاً لا يجوز أن يغيّر مستنداً سابقاً** |
| **القاعدة** | `GR-32` · `BR-M5-05` · `BR-M7-10` — **والتكرار هنا مقصود لا شذوذ تطبيع** |

### `PAT-07` — المشتقّ المُعاد بناؤه (Derived Read Model)
| البند | التفصيل |
|---|---|
| **متى** | الأرصدة · الملخصات · المركز المعلّق · بنود المتبقي المتأخر |
| **لماذا هنا** | أداء وتكلفة (`ADR-0008`) |
| **القاعدة الحاسمة** | **المشتقّ ليس مصدر حقيقة** — **وقابل لإعادة البناء بالكامل من الدفتر**، وأي تعارض يُحسَم **لصالح الدفتر دائماً** |

### `PAT-08` — العملية القابلة للتكرار بلا أثر (Idempotent Operation)
| البند | التفصيل |
|---|---|
| **متى** | **كل عملية سحابية مشغَّلة** · وكل حفظ من الجهاز |
| **لماذا هنا** | **شرط صحة لا تحسين**: المشغّل قد يُنفَّذ مرتين، **والتراكم على قيمة سابقة يُنتج رقماً مضاعفاً بلا إنذار** |
| **القاعدة** | إعادة البناء **من الدفتر بالكامل** لا `+=` · والحفظ **بمعرّف مُولَّد مسبقاً** يمنع الازدواج |

### `PAT-09` — التحقق كنتيجة لا كاستثناء (Result Type)
| البند | التفصيل |
|---|---|
| **متى** | كل قاعدة عمل في طبقة النطاق |
| **لماذا هنا** | **القاعدة المخالَفة نتيجة متوقّعة لا حالة استثنائية** — والاستثناءات للفشل غير المتوقّع |
| **القاعدة** | `validate…` ترجع نتيجة تحمل **رمز الرسالة من كتالوج `§11`** لا نصاً خاماً |

### `PAT-10` — الحارس بالصلاحية (Permission Guard)
| البند | التفصيل |
|---|---|
| **متى** | كل شاشة وكل عنصر محكوم بصلاحية |
| **لماذا هنا** | الصلاحية **تقاطع ثلاثة محاور** (شاشة × زر/حقل × نطاق مصدر) |
| **القاعدة الحاسمة** | **الحارس في الواجهة تجربة، والحماية في قواعد الحماية** — **ولا يجوز الاكتفاء بالأول أبداً** (`ADR-0002`) |
| **مثال** | إخفاء عمود السعر كلياً عمّن لا يملك «عرض أسعار التوزيع» (`ت-12`) |

## 3. أنماط الواجهة

### `PAT-11` — الحالات الأربع الإلزامية
كل شاشة **تُصرِّح صراحةً** بحالاتها: **تحميل · فارغة · خطأ · محتوى** —
ولا يُسمح بشاشة بلا حالة فارغة أو بلا حالة خطأ.

### `PAT-12` — الدلالة الموحّدة للقيمة المعلّقة
**⏳ برتقالية في خمسة مواضع** (الحقل · السطر · رأس الشاشة · لوحة التحكم ·
التصدير) — **بنفس الشكل في كل النظام** (`FR-SYS-03`).

### `PAT-13` — التنبيه المتدرّج بالعمر
**🟡 يوم–يومان · 🟠 3–4 · 🔴 5 فأكثر** للمتبقي المتأخر — **بنفس التدرّج
في البطاقة والقائمة والتقرير** (`BR-M8-07`).

### `PAT-14` — النموذج متعدد السطور بإجماليَين
كل مستند سطوري يعرض **إجمالي الحبات وإجمالي الأوزان منفصلين دائماً**
(`GR-19`) — **ولا يوجد إجمالي واحد جامع في أي شاشة**.

## 4. أنماط مرفوضة صراحةً

| المرفوض | لماذا |
|---|---|
| **Active Record** (الكيان يعرف كيف يحفظ نفسه) | يخلط النطاق بالتخزين ويُفقد النطاق نقاءه |
| **Singleton عام قابل للتغيير** | يُخفي الاعتماديات ويُفشل الاختبار المعزول |
| **حركة عكسية / تصحيحية** | **مرفوض بقرار معماري** (`ADR-0004`) |
| **حذف ناعم بحقل `deleted`** | البديل المعتمد **الوسم بـ«ملغى»** بسبب نصي — والحذف مرفوض أصلاً |
| **تخزين مؤقت على الجهاز** | يناقض `ADR-0003` |
| **مخزن حالة عام واحد لكل التطبيق** | يخلط حالة الشاشة بحالة التطبيق (`ADR-0010`) |
| **Service Locator** | حقن الاعتمادية الصريح أوضح وأسهل اختباراً |
| **تجريد استباقي لواجهة بتنفيذ واحد** | تعقيد بلا مقابل — يُضاف عند الحاجة الثانية |
