# خطة الاستجابة للحوادث — QTMS

| البند | القيمة |
|---|---|
| **الإلزامية** | **M** |
| **الطبيعة** | LIVING |
| **المالك** | DEVOPS / SEC |

> **مستند إضافي خارج قائمة UPDS-00 للمجلد** — أُضيف لأن النظام **يدير ذمماً
> حقيقية**، ★ **وحادثة البيانات فيه أخطر من حادثة التوقف**.

---

## 1. تصنيف الحوادث

| المستوى | التعريف | مثال | الاستجابة |
|---|---|---|---|
| ⛔ **P0 — بيانات** | ★ **تشويه أو فقدان بيان مالي · تجاوز تفويض** | رصيد لا يطابق دفتره · وصول لمصدر خارج النطاق | ★ **فوري — تجميد الكتابة أولاً** |
| 🔴 **P1 — توقف** | النظام غير قابل للاستخدام | القاعدة لا تستجيب | فوري |
| 🟠 **P2 — تعطّل جزئي** | وحدة معطّلة ولها بديل | تقرير لا يُفتح | خلال اليوم |
| 🟡 **P3 — إزعاج** | خلل محدود الأثر | بطء شاشة | حسب الأولوية |

> ★ **P0 أخطر من P1:** ★ **التوقف يُلاحَظ ويُصلَح — والرقم الخاطئ يُصدَّق
> ويُبنى عليه قرار مالي، وقد لا يُكتشَف أبداً.**

## 2. ★ إجراء P0 — حادثة بيانات

```text
① ★ جمّد الكتابة فوراً        ⟵ منع تشويه إضافي — قبل أي تحليل
② حدّد النطاق                 ⟵ أي دفاتر؟ أي أيام؟ أي مصادر؟
③ ⛔ لا تُصحّح شيئاً يدوياً
④ ★ اقرأ الدفاتر — هي مصدر الحقيقة الوحيد
⑤ حدّد السبب: خلل كود؟ تباعد ملخصات؟ تدخّل بشري؟
⑥ ★ أصلح السبب أولاً — ثم أعد بناء الملخصات من الدفاتر
⑦ تحقق: كل رصيد يطابق دفتره
⑧ افتح الكتابة + قيد في سجل التدقيق + بلاغ للمالك
⑨ تقرير حادثة كامل
```

> ★ **الخطوة ① قبل كل شيء:** كل دقيقة كتابة إضافية **توسّع دائرة التشويه**
> وتزيد صعوبة إعادة البناء.

## 3. إجراء P1 — توقف

```text
① تحقق: هل العطل عندنا أم في المنصة السحابية؟
② أبلغ المستخدمين — ★ العمل متوقف فعلياً لا بطيء
③ إن كان بسبب نشر حديث ⟵ خطة التراجع
④ إن كان من المنصة ⟵ تابع حالة المزوّد وأبلغ
⑤ بعد العودة: ★ تحقق من سلامة البيانات قبل إعلان الانتهاء
```

## 4. الأدوار

| الدور | المسؤولية |
|---|---|
| **قائد الحادثة** | ★ **شخص واحد يقرر** — لا قرارات موزّعة تحت الضغط |
| **المنفّذ التقني** | التشخيص والإصلاح |
| **حلقة الوصل** | إبلاغ المالك والمستخدمين |

> ★ **في فريق صغير قد يجتمع الدوران في شخص** — لكن **قائد الحادثة يُسمّى صراحةً**.

## 5. الإبلاغ

| الجهة | متى |
|---|---|
| ★ **المالك** | ★ **كل حادثة P0 — فوراً وبلا تأخير** |
| **المستخدمون** | عند التوقف أو أثر على بياناتهم |
| **الفريق** | كل الحوادث |

| القاعدة |
|---|
| ★ **لا إخفاء لحادثة بيانات** — ★ **الاكتشاف المتأخر يهدم الثقة بالنظام كله** |
| **الرسالة تصف الأثر والإجراء — لا التفاصيل التقنية** |
| ⛔ **لا تفاصيل ثغرة أمنية قبل الإصلاح** |
