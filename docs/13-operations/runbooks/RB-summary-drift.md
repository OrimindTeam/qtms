# RB-summary-drift — ★ تباعد الملخصات عن الدفاتر

| البند | القيمة |
|---|---|
| **الأولوية** | 🔴 **عالية** |
| **الخطر المرتبط** | `RISK-08` · `DEBT-01` · `DEBT-02` |

---

## 1. متى يُستخدَم

| العرَض |
|---|
| **رصيد معروض لا يطابق مجموع حركات دفتره** |
| **بطاقة ضمار المالك لا تطابق التفاصيل** |
| **تقرير يعرض رقماً يخالف كشف الحساب** |
| **فشل عملية سحابية لبناء الملخصات** |
| ★ **بعد أي استرجاع أو تراجع** |

## 2. ⛔ ما لا تفعله

| # | ممنوع |
|---|---|
| 1 | ⛔ **لا تُصحّح الرصيد بالكتابة عليه** — ★ **الرصيد نتيجة لا قيمة** |
| 2 | ⛔ **لا تحذف الملخص المتباعد** — أعد بناءه |
| 3 | ⛔ **لا تعدّل حركة دفتر لتوافق الملخص** — ★ **الاتجاه معكوس تماماً** |
| 4 | ⛔ **لا تفترض أن الملخص صحيح** — ★ **الدفتر هو الحقيقة دائماً** (`ADR-0008`) |

## 3. الخطوات

```text
① حدّد النطاق: أي دفتر؟ أي مصدر؟ أي أيام؟
② ★ اقرأ حركات الدفتر واحسب المجموع يدوياً
③ قارن بالملخص وسجّل الفرق
④ ابحث عن السبب:
      • فشل عملية سحابية؟         ⟵ راجع سجلات الفشل
      • تراكم بدل إعادة بناء؟      ⟵ ★ خلل كود — بلّغ فوراً
      • تصفية متأخرة لم تُعِد البناء؟ ⟵ ★ السبب الأشيع
      • استرجاع أو تراجع حديث؟     ⟵ متوقَّع
⑤ ★ أعد بناء ملخصات النطاق من الدفاتر ⟵ ★★ RB-rebuild-summaries §4
⑥ ★ إن كانت تصفية بأثر رجعي: تأكد من إعادة بناء اليوم الأصلي ووسمه
⑦ تحقق (§4)
⑧ قيد في سجل التدقيق + بلاغ للمالك
```

## 4. التحقق من النجاح

- [ ] ★ **الرصيد = مجموع حركات دفتره** — لكل دفتر في النطاق
- [ ] **بطاقة ضمار المالك تطابق تفاصيلها**
- [ ] ★ **إعادة تشغيل البناء مرة أخرى لا تُغيّر شيئاً** (idempotent)
- [ ] **لا ملخص آخر في نفس النطاق متباعد**

## 5. متى تُصعّد

| الحالة |
|---|
| ★ **الفرق يعود بعد إعادة البناء** ⟵ **خلل كود — حاجب** |
| ★ **إعادة البناء تُنتج نتيجة مختلفة كل مرة** ⟵ **ليست idempotent — حاجب** |
| **الفرق يمسّ ذمة عميل فعلية** ⟵ **بلاغ فوري للمالك** |
