# RB-user-lockout — مستخدم لا يستطيع الدخول أو العمل

| البند | القيمة |
|---|---|
| **الأولوية** | 🟠 **متوسطة** — ★ **وترتفع في ساعة الذروة** |

---

## 1. متى يُستخدَم

| العرَض |
|---|
| المستخدم لا يستطيع الدخول |
| يدخل لكن لا يرى بياناته |
| **يرى الشاشة لكن العملية تُرفَض** |
| **التطبيق لا يعمل على جهازه** |

## 2. ⛔ ما لا تفعله

| # | ممنوع |
|---|---|
| 1 | ⛔ **لا تمنح صلاحية أوسع «لحل المشكلة مؤقتاً»** — ★ **التوسيع المؤقت يبقى دائماً** |
| 2 | ⛔ **لا توسّع نطاق مصادره لتجاوز عائق** |
| 3 | ⛔ **لا تشارك حساباً آخر** — ★ **يهدم عدم الإنكار** |
| 4 | ⛔ **لا تخفّف قاعدة حماية** |

## 3. التشخيص

```text
① هل الحساب مفعَّل؟            ⟵ معطَّل ⟵ ★ تحقق لماذا قبل التفعيل
② هل الجهاز يحمل خدمات المنصة؟ ⟵ لا ⟵ ★ الجهاز غير مدعوم — ليس خللاً
③ هل يوجد اتصال؟               ⟵ لا ⟵ ★ النظام لا يعمل بلا اتصال — بالتصميم
④ هل إصدار التطبيق حديث؟       ⟵ قديم ⟵ التحديث
⑤ هل الدور والصلاحيات صحيحة؟   ⟵ راجع كتالوج الصلاحيات
⑥ هل المصدر ضمن نطاقه؟         ⟵ ★ السبب الأشيع للرفض غير المفهوم
⑦ هل الرمز مُحدَّث بعد تغيير صلاحية؟ ⟵ إعادة دخول
```

## 4. ★ الحالة الأشيع

> ★ **«أرى الشاشة لكن العملية تُرفَض» = نطاق المصادر غالباً.**
>
> **الصلاحية موجودة والمصدر خارج النطاق.** ★ **والعلاج ليس منح صلاحية أوسع
> بل تصحيح النطاق إن كان ناقصاً فعلاً — بقرار من المخوَّل.**

## 5. التحقق من النجاح

- [ ] **المستخدم يعمل طبيعياً**
- [ ] ★ **بلا توسيع صلاحية غير مبرَّر**
- [ ] **التغيير مُسجَّل في سجل التدقيق**
- [ ] ★ **إن كان السبب غموض رسالة الرفض ⟵ بند تحسين واجهة**

## 6. متى تُصعّد

| الحالة |
|---|
| ★ **المستخدم يصل لما لا يخصّه** ⟵ ⛔ **حادثة أمنية P0** |
| **رفض غير مفسَّر بأي من §3** ⟵ **خلل في القواعد** |
| **يتكرر مع مستخدمين كثر** ⟵ **خلل نظامي لا فردي** |
