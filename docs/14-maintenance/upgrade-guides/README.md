# أدلة الترقية — QTMS

| البند | القيمة |
|---|---|
| **الطبيعة** | LOG |
| **المالك** | DEV |
| **الحالة** | ⏳ **لا أدلة — لم يبدأ التنفيذ** |

---

## 1. التسمية

```text
upgrade-<من>-to-<إلى>.md        مثال: upgrade-1.x-to-2.0.md
```

## 2. ★ متى يُكتَب دليل

> ★ **إلزامي مع كل تغيير كاسر** — راجع
> [`../../12-deployment-and-release/versioning-scheme.md`](../../12-deployment-and-release/versioning-scheme.md) §2.

| المحفّز |
|---|
| ★ **تغيير معنى حقل أو معادلة** |
| **تغيير يستلزم ترحيل بيانات** |
| **تغيير عقد استدعاء عملية سحابية** |
| ★ **تغيير في التفويض يُلغي وصولاً قائماً** |

## 3. ★ القالب

```markdown
# الترقية من <س> إلى <ص>

## ما تغيّر ولماذا
## ★ هل تتأثر بيانات قائمة؟      ← ★ أول سؤال دائماً
## ★ خطوات الترحيل بالترتيب
## ★ نقطة اللاعودة               ← ★ بعد أي خطوة يستحيل التراجع؟
## التحقق بعد الترقية
## خطة التراجع
## الأثر على المستخدمين
```

## 4. ★ قواعد ملزمة

| # | القاعدة |
|---|---|
| 1 | ★ **نسخة احتياطية قبل أي ترقية تمسّ البيانات** |
| 2 | ★ **تُجرَّب على التجريبية ببيانات مشابهة أولاً** |
| 3 | ★ **إضافة لا تعديل** — ⛔ **لا إعادة تسمية ولا تغيير معنى** |
| 4 | ★ **بعد الترقية: كل رصيد يطابق دفتره** |
| 5 | ★ **عيّنة مستندات قديمة تُقرَأ بمعناها الأصلي** |
| 6 | **سطر في** [`../../06-database/migrations-log.md`](../../06-database/migrations-log.md) |
| 7 | ★ **`ADR` يشرح لماذا كان الكسر ضرورياً** |

> مالية حيّة.**
>
> ★ **الوقاية الوحيدة: الحقل موجود من اليوم الأول.**
