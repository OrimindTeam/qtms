## 1. دليل الرموز

| الرمز | المعنى |
|---|---|
| **R** (Responsible) | مَن ينفّذ العمل فعلياً |
| **A** (Accountable) | مَن يُساءَل عن النتيجة ويملك قرار الاعتماد — **واحد فقط لكل صف** |
| **C** (Consulted) | يُستشار قبل الاعتماد |
| **I** (Informed) | يُبلَّغ بعد الاعتماد |

## 4. مسؤوليات لا تُفوَّض في هذا المشروع تحديداً

هذه بنود رفعها المستند المصدر إلى مستوى «حرج»، فلا يجوز أن تبقى مسؤوليتها
ضمنية:

| المسؤولية | صاحب **A** | لماذا لا تُفوَّض |
|---|---|---|
| **كتابة قواعد الحماية ومراجعتها** (ترجمة جدول 6.5 و9.6 حرفياً) | **SEC** | «أي قاعدة عمل بلا مقابل مكتوب في قواعد الحماية تُعتبر غير مُنفَّذة أمنياً» (`BR-M1-07` · §9.7). هذه **طبقة التفويض الوحيدة المعتمدة** في النظام. |
| **منح الصلاحيات وتحديد نطاق المصادر** | **CLIENT** (المالك) | «تحديد نطاق المصادر» موصوفة في §9.3 بأنها **أخطر صلاحية في النظام**، ومقصورة على الدور R1 (المالك) وحده. |
| **الاطّلاع على سحبيات المالك** | **CLIENT** | بيانات شخصية حساسة — «ممنوعة افتراضياً لكل الأدوار عدا المالك والمدير» (§9.2). |
| **كتابة الإعداد التأسيسي** (M21) | **CLIENT** | مرة واحدة، من المالك حصراً، وتصحيحها لاحقاً يتطلب تدخلاً على مستوى المشروع السحابي (`BR-M21-04`). |
| **توقيع `uat-signoff.md`** | **CLIENT** | بوابة النشر الإنتاجي — فعل بشري حصري (UPDS-05 §4.6). |
| **اعتماد أي `ADR`** | **ARCH** | Claude Code يصوغ الصياغة، **والقرار بشري** (UPDS-05 §8). |

## 5. حدود صلاحية Claude Code (CC)

| يفعله بلا انتظار | يقترحه وينتظر اعتماداً | **لا يفعله إطلاقاً** |
|---|---|---|
| هيكلة المستندات وتوليد المسودات | `module-design/*` · `test-cases/*` · `runbooks/*` | اعتماد أي بوابة حَوْكمة |
| تحديث `erd.md` · `data-dictionary.md` · `migrations-log.md` بعد تغيير فعلي | `technical-debt-register.md` · `status-reports/*` | تعديل ADR معتمد أو `srs.md` معتمد أو `uat-signoff.md` موقَّعاً |
| تحديث `developer-onboarding.md` من الفهرس الفعلي | `troubleshooting-guide.md` | كتابة أي سرّ في أي مستند أو كود |
| توليد `changelog.md` من الالتزامات | صياغة ADR جديد بحالة «مقترح» | حذف أي مستند نهائياً |
