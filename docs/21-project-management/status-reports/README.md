# تقارير الحالة — QTMS

| البند | القيمة |
|---|---|
| **الطبيعة** | LOG |
| **المالك** | PM |
| **الحالة** | ✅ **محدَّد — تقرير لكل زيادة** (`OQ-000`) |

---

## 0. ★ الإيقاع المعتمد

> ★ **المنهجية تزايدية** — ★ **فالتقرير يُكتب عند اكتمال كل زيادة، لا بالتقويم.**
> [`../development-methodology.md`](../development-methodology.md).

```text
✅ تقرير عند اكتمال كل زيادة
⛔ لا تقرير أسبوعي ولا شهري دوري بلا حدث يستدعيه
```

> ★ **لماذا؟** ★ **التقرير الدوري بلا حدث يُنتج نصاً مكرراً لا يقرؤه أحد**،
> ★ **والتقرير عند الاكتمال يحمل معلومة حقيقية: قدرة جديدة صارت قابلة للاستخدام.**

## 1. التسمية

```text
status-<التاريخ>-INC-<رقم>.md
```

## 2. ★ المحتوى

| القسم | ملاحظة |
|---|---|
| ★ **الزيادة المكتملة** | ★ **رقمها ونطاقها وما صار المستخدم قادراً على فعله** |
| ★ **معيار قبولها** | ★ **هل تحقق حرفياً؟** |
| **الزيادة التالية المخطَّطة** | ★ **واحدة فقط — لا قائمة طويلة** |
| ★ **البنود المفتوحة الحاجبة** | ★ **`OQ` · `RD` · `RF` — وأثر كل منها** |
| ★ **المخاطر المتغيّرة** | جديدة أو تصاعدت |
| ★ **التقدّم** | ★ **عدد الزيادات المنجزة من المخطَّطة للمعلم** |
| ★ **نسبة اكتمال التوثيق** | من `track_completion.py` |
| ★ **حالة الديون الحاجبة** | `DEBT-01` · `RISK-01` · `DEBT-06` |
| **ما يحتاج قراراً من المالك** | ★ **صريحاً لا ضمناً** |

## 3. ★ قواعد

| # | القاعدة |
|---|---|
| 1 | ★ **الصدق قبل التفاؤل** — ★ **التأخير المعلَن أرخص من المفاجأة** |
| 2 | ★ **البند الحاجب يُذكَر في صدر التقرير** لا في ذيله |
| 3 | ⛔ **لا بيانات مالية حقيقية في التقرير** |
| 4 | **كل بند يشير لمعرّفه في `docs/`** |
