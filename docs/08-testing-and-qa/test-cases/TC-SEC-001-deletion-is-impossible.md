# TC-SEC-001 — ★ استحالة الحذف (لكل الأدوار بما فيها المالك)

| البند | القيمة |
|---|---|
| **المستوى** | تكامل (قواعد الحماية) |
| **الأولوية** | 🔴 **حرجة — بوابة نشر** |
| **يغطّي** | ★ **قاعدة «لا حذف نهائياً»** · `A-14` · سلامة سجل التدقيق |
| **النوع** | ⛔ **نفي** |

---

## 1. المبدأ

```text
★ لا يوجد في هذا النظام مسار حذف فعلي لأي بيان — لأي مستخدم.
   والإلغاء يكون بوسم «ملغى» لا بمحو.
   ⛔ والمالك نفسه لا يُستثنى.
```

## 2. الأدوار المُختبَرة

| الدور | يجب أن يُرفَض؟ |
|---|:-:|
| مستخدم محدود | ⛔ نعم |
| محاسب | ⛔ نعم |
| أمين مخزن | ⛔ نعم |
| ★ **المالك** | ⛔ **نعم — وهذا جوهر الاختبار** |

## 3. الأهداف المُختبَرة

| # | المحاولة |
|:-:|---|
| 1 | حذف حركة دفتر |
| 2 | حذف مستند تشغيلي (توزيعة · سند قبض · سند خصم · جونية) |
| 3 | ★ **حذف قيد في سجل التدقيق** |
| 4 | حذف سجل تهيئة مستخدَم (مقوت · رعوي · مصدر) |
| 5 | ★ **حذف مجموعة كاملة** |
| 6 | حذف سجل تعديل مستند |

## 4. ★ أسلوب التنفيذ — إلزامي

```text
① احصل على رمز مصادقة للدور المُختبَر
② أرسل طلب الحذف مباشرة للقاعدة — ⛔ بلا مرور بالتطبيق إطلاقاً
③ ★ يجب أن يُرفَض من قواعد الحماية نفسها
```

> ★ **الاختبار عبر الواجهة لا قيمة له هنا** — إخفاء زر الحذف **ليس حماية**،
> والمهاجم لا يستخدم شاشتك.

## 5. معيار النجاح

- [ ] ★ **كل محاولة في §3 × كل دور في §2 ⟵ مرفوضة**
- [ ] **الرفض من قواعد الحماية لا من التطبيق**
- [ ] **البيان ما زال موجوداً وسليماً بعد المحاولة**
- [ ] **الإلغاء المشروع يعمل بوسم «ملغى» لا بمحو**

## 6. عند الفشل

> ⛔ **فشل أي بند ⟵ يوقف النشر فوراً.** فقدان بيان مالي **لا يُسترجَع**،
> **وسجل تدقيق قابل للحذف يهدم مبرر التعديل المباشر كله** (`ADR-0004`).
