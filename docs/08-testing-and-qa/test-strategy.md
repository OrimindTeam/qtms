# استراتيجية الاختبار — QTMS

| البند | القيمة |
|---|---|
| **الإلزامية** | **M** |
| **الطبيعة** | LIVING |
| **المالك** | QA + DEV |
| **المرجع** | ISO/IEC/IEEE 29119 |

> ★ **المبدأ الحاكم:** الاختبار هنا **ليس فحص «هل يعمل؟» بل «هل الرقم صحيح؟»**.
> تطبيق يعمل بسلاسة ويُخرج رصيداً خاطئاً **أسوأ من تطبيق ينهار** — لأن
> الانهيار ظاهر، **والرقم الخاطئ يُصدَّق ويُبنى عليه قرار مالي**.

## 2. هرم الاختبار

```text
              ▲   يدوي/قبول المالك   ← السيناريوهات المالية الكاملة
             ███  E2E                 ← قليل · مسارات حرجة فقط
           ██████ تكامل + قواعد حماية ← ★ ثقيل عمداً في هذا المشروع
      ████████████ وحدة (المعادلات)   ← ★ الأثقل والأسرع
```

| الطبقة | ماذا تغطي | أين |
|---|---|---|
| **وحدة** | ★ **كل معادلة · كل قاعدة عمل حسابية · التقريب · الوحدات** | طبقة المجال |
| **تكامل** | المعاملات · الدفاتر · إعادة البناء · العدّادات | المحاكي المحلي |
| ★ **قواعد الحماية** | ★ **كل صلاحية إثباتاً ونفياً** | ★ **المحاكي المحلي — إلزامي** |
| **واجهة** | الحالات الأربع · RTL · التكبير | اختبارات مكوّنات |
| **E2E** | مسارات اليوم الكاملة | جهاز/محاكٍ |
| **قبول** | `AT-*` + سيناريو §15 | يدوي بحضور المالك |

> ★ **الهرم هنا منتفخ في الوسط عمداً:** لأن **طبقة التفويض الوحيدة هي قواعد
> الحماية** (لا خادم وسيط) — فاختبارها **ليس طبقة مساعدة بل بوابة أمنية**.

## 3. ★ الاختبار المالي — الأسلوب الملزم

| # | القاعدة |
|---|---|
| 1 | ★ **الأرقام المتوقَّعة من المستند المصدر لا من تشغيل الكود** — «سجّل ما أخرجه البرنامج كمتوقَّع» **يُثبّت الخطأ لا يكشفه** |
| 2 | ★ **سيناريو §15 الكامل حالة اختبار مرجعية دائمة** — كل رقم فيه محسوب ومتوازن |
| 3 | **كل معادلة تُختبَر بـ: قيمة عادية · صفر · حدّ · قيمة تُنتج كسراً** |
| 4 | ★ **اختبار «لا فاصلة عائمة»** صريح على أنواع المبالغ — ★ **وأن نوعها `int` فعلاً** ⛔ **لا عشري ولا «أصغر وحدة»** (`ADR-0015`) |
| 4-ب | ★ **اختبار قاعدة التقريب بحالتيها الحدّيتين:** `617.25 ⟵ 617` · `617.50 ⟵ 618` — ★ **وأن إدخال المستخدم بكسر يُرفض لا يُقرَّب** |
| 5 | ★ **اختبار عدم قابلية الجمع** بين الحبات والأوزان |
| 6 | ★ **اختبار التوازن**: مجموع حركات الدفتر = الرصيد المعروض — **بعد كل عملية** |
| 7 | **اختبار إعادة البناء**: تشغيلها مرتين يُنتج نفس النتيجة (idempotent) |
| 8 | ★ **اختبار الأثر الرجعي**: تصفية متبقٍّ متأخر تُعيد بناء ملخصات اليوم الأصلي |

## 4. ★ الحالات التي يجب أن **تفشل** — اختبار النفي

> **نصف قيمة الاختبار هنا في إثبات أن الممنوع ممنوع فعلاً.**

| # | يجب أن تُرفَض |
|---|---|
| 1 | **حذف أي مستند أو حركة** — لأي مستخدم **بمن فيهم المالك** |
| 2 | **تعديل أو مسح قيد في سجل التدقيق** |
| 3 | **تعديل مبلغ بلا سبب نصّي** |
| 4 | **توزيعة ثانية لنفس المقوت في نفس المصدر في نفس اليوم** (`GR-18`) |
| 5 | **قراءة أو كتابة خارج نطاق مصادر المستخدم** |
| 6 | **عملية بلا صلاحية** — ولو أُرسلت مباشرة متجاوِزة الواجهة |
| 7 | **كتابة تُنشئ رصيداً لا يطابق دفتره** |
| 8 | **حفظ ينجح بلا اتصال** |

> ★ **البند 6 جوهري:** الاختبار يجب أن **يتجاوز الواجهة ويكتب مباشرة** —
> فهذا ما يفعله المهاجم فعلاً، وهذا وحده يُثبت أن الحماية سحابية.

## 6. التغطية

| النطاق | الهدف |
|---|---|
| ★ **طبقة المجال (المعادلات)** | ★ **100٪ — بلا استثناء** |
| ★ **قواعد الحماية** | ★ **كل قاعدة: حالة سماح + حالة منع** |
| العمليات السحابية | ≥ 80٪ 🔶 |
| الواجهة | المسارات الحرجة + الحالات الأربع |
| **مجمل المشروع** | ≥ 70٪ 🔶 |

> 🔶 = **أهداف قياسية أضفناها** — المصدر لم يحدد نسب تغطية.
> ⚠️ **النسبة ليست غاية:** 100٪ تغطية بمتوقَّعات مأخوذة من مخرجات الكود **لا
> تساوي شيئاً**. المعيار الحقيقي: **هل الرقم المتوقَّع مصدره المستند؟**

## 7. الانحدار

| متى | ماذا |
|---|---|
| **كل دمج** | كل الاختبارات الآلية |
| ★ **كل تغيير يمسّ معادلة** | ★ **سيناريو §15 كاملاً** |
| **كل تحديث اعتمادية** | المجموعة الكاملة |
| **قبل كل إصدار** | كامل + قبول يدوي |
| **بعد كل إصلاح خلل** | ★ **اختبار يُثبت الخلل ثم يُثبت زواله** |

## 8. ما لا نختبره ولماذا

| البند | السبب |
|---|---|
| **موثوقية المنصة السحابية نفسها** | مسؤولية المزوّد |
| **أجهزة بلا خدمات Google Play** | **غير مدعومة صراحةً** |
| **العمل دون اتصال** | ★ **غير موجود بالتصميم** — والاختبار هو **أن الحفظ يُمنَع** |
| **وحدة النسخ الاحتياطي داخل التطبيق** | **محذوفة في 2.2** |
| **التحليلات التنبؤية** | خارج النطاق (المرحلة الرابعة) |
