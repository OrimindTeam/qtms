## 1. الصيغة

```text
MAJOR . MINOR . PATCH        مثال: 1.4.2
```

| الجزء | يزيد عند |
|---|---|
| **MAJOR** | ★ **تغيير كاسر** — راجع §2 |
| **MINOR** | قدرة وظيفية جديدة متوافقة |
| **PATCH** | إصلاح خلل بلا تغيير سلوك مقصود |

## 2. ★ ما يُعدّ كاسراً في هذا المشروع

> **المفهوم مختلف هنا: لا واجهة برمجية عامة.** ★ **الكسر يكون في البيانات
> أو المعنى المحاسبي:**

| # | التغيير | لماذا كاسر |
|:-:|---|---|
| 1 | ★ **تغيير معنى حقل قائم** | ★ **يُنتج تفسيراً خاطئاً لبيانات تاريخية بصمت** |
| 2 | ★ **تغيير معادلة تُنتج رقماً مختلفاً لنفس المدخلات** | **أرقام تاريخية تتغيّر** |
| 3 | **تغيير عقد استدعاء عملية سحابية** | نسخ قديمة تنكسر |
| 4 | **إضافة حقل إلزامي بلا قيمة افتراضية** | القديم لا يُقرأ |
| 5 | ★ **تغيير في التفويض يُلغي وصولاً قائماً** | يمسّ عمل المستخدمين |
| 6 | **تغيير يستلزم ترحيل بيانات** | — |

| القاعدة |
|---|
| ★ **التغيير الكاسر يستلزم `ADR` + دليل ترقية في** [`../14-maintenance/upgrade-guides/`](../14-maintenance/upgrade-guides/) |
| ★ **وسطراً في** [`../06-database/migrations-log.md`](../06-database/migrations-log.md) |

## 3. قبل الإصدار الأول

```text
0.y.z  ⟵ ما قبل الإنتاج
1.0.0  ⟵ ★ أول نشر إنتاجي بذمم حقيقية
```

> ★ **`1.0.0` ليست علامة نضج تقني بل التزاماً:** **من هذه اللحظة توجد بيانات
> مالية حقيقية لا يجوز كسرها.**

## 4. رقم البناء

| البند | القاعدة |
|---|---|
| **رقم البناء** | **يزيد مع كل حزمة — ولا ينقص أبداً** |
| **الاسم المعروض** | `MAJOR.MINOR.PATCH` |
| ★ **الإصدار ظاهر في التطبيق** | ★ **يُسهّل التشخيص الميداني** |

## 5. الوسم

```text
v1.4.2     ⟵ وسم على الالتزام المنشور
```

| القاعدة |
|---|
| **كل إصدار إنتاجي موسوم** |
| **الوسم لا يُحرَّك بعد النشر** |
| **مرتبط بملاحظات إصدار في** [`release-notes/`](release-notes/) |

## 6. ★ الحد الأدنى للإصدار الإلزامي

> **في التوزيع المباشر لا تحديث تلقائي.** ★ **فيجب أن يعرف التطبيق حداً أدنى
> للإصدار المقبول** — ويُلزم المستخدم بالتحديث تحته.

| متى يُرفَع الحد الأدنى |
|---|
| ★ **إصلاح خلل مالي** |
| ★ **إصلاح ثغرة أمنية** |
| **تغيير بنيوي لا يقرؤه القديم بمعناه الصحيح** |
