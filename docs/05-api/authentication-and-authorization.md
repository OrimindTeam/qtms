# المصادقة والتفويض — QTMS

| البند | القيمة |
|---|---|
| **الإلزامية** | **M** — **تُقرأ إلزامياً قبل أي عمل أمني** |
| **الطبيعة** | **STATIC** |
| **المالك** | SEC / DEV |
| **يعتمد على** | `ADR-0002` |

---

## 1. المصادقة (Authentication)

| البند | القرار |
|---|---|
| **الخدمة** | خدمة مصادقة مُدارة (Firebase Authentication) |
| **الهوية** | **البريد/اسم الدخول** — فريد |
| **كلمة المرور** | **تديرها الخدمة بالكامل**: الإنشاء · التشفير · إعادة التعيين · قفل الحساب — **ولا تُخزَّن في قاعدة البيانات إطلاقاً** |
| **الجلسة** | **محدودة المدة** · وتُبطَل فوراً عند تعطيل المستخدم |
| **قفل الحساب** | **بعد عدد محاولات فاشلة متتالية** (`BR-M1-05`) |
| **معرّف الجهاز** | **لا يُخزَّن في بطاقة المستخدم** — التتبّع في سجل التدقيق فقط |
| **حماية العميل** | **فحص العميل الرسمي** يسبق كل طلب — يرفض أي عميل غير التطبيق |

## 2. التفويض (Authorization) — ثلاثة محاور معاً

```text
   المحور ١ : الوحدة/الشاشة        →  هل يرى الشاشة أصلاً؟
        ×
   المحور ٢ : الزر/الحقل التفصيلي  →  هل يملك هذا الزر أو هذا الحقل بعينه؟
        ×
   المحور ٣ : نطاق المصدر           →  هل هذا المصدر ضمن مصادره المسموحة؟
        ↓
   ✅ مسموح   /   ❌ مرفوض من طبقة الحماية (لا من إخفاء الزر)
```

> **قاعدة الحسم:** **غياب أي محور من الثلاثة ⟵ رفض** — ولو كان الزر ظاهراً
> بالخطأ في الواجهة.

## 3. حمل الصلاحيات — المطالبات المخصّصة

```json
{
  "role": "<معرّف الدور>",
  "permissions": { "<مفتاح الصلاحية>": true },
  "sourceScope": "all" | ["<sourceId>", "..."]
}
```

> ⚠️ **مُحدَّث بـ`ADR-0016` (2026-08-24) — والصيغة أعلاه لم تعد كاملة:**
> ★ **خريطة `permissions` خرجت من الرمز إلى `users/{userId}`** لأن حمولتها
> **1707 بايت والحدّ 1000**. ✅ **و`role` و`sourceScope` يبقيان في الرمز.**

**الصيغة السارية فعلياً بعد `ADR-0016`:**

```json
// في رمز الدخول
{ "role": "<معرّف الدور>", "sourceScope": "all" | ["<sourceId>", "..."] }

// وفي users/{userId}
{ "permissions": { "<مفتاح الصلاحية>": true } }
```

| البند | القاعدة |
|---|---|
| **الموضع** | ★ **`role` و`sourceScope` في الرمز · و`permissions` في `users/{userId}`** |
| **الكتابة** | **عبر عملية سحابية حصراً** — والكتابة من التطبيق **مرفوضة** |
| **التحديث** | ★ **الصلاحية تسري فوراً** — ⛔ **ولم تعد تنتظر إعادة إصدار الرمز**، لأنها تُقرأ من المستند. **ونطاق المصادر وحده** يحتاج تحديث الرمز |
| **القراءة في القواعد** | ★ **`get()` واحدة** على `users/{uid}` بمسار حرفي ثابت — مُخزَّنة داخل التقييم الواحد. ⛔ **وثمنها المعلَن قراءة مفوترة لكل عملية** |
| **القراءة في التطبيق** | `role`/`sourceScope` **محلياً من الرمز** · و`permissions` **من بطاقة المستخدم** (وهي مقروءة لصاحبها وحده) |

## 4. نطاق المصادر — **قيد أمني لا فلتر عرض**

| القيمة | المعنى |
|---|---|
| **`all`** | يرى ويكتب في كل المصادر الحالية **وأي مصدر يُضاف مستقبلاً تلقائياً** |
| **قائمة محددة** | **وأي مصدر جديد لا يُضاف لها تلقائياً** بل يحتاج منحاً صريحاً |

**الأثر الملزم على كل شاشة:**

| الشاشة | الأثر |
|---|---|
| قوائم اختيار المصدر | **لا تظهر فيها إلا مصادره** |
| المخزون · المتبقي المتأخر · التسعير · التوزيع · البيع النقدي | مقيَّدة بمصادره |
| المقبوضات والخصومات | **لا تظهر له إلا ضمارات مصادره** |
| **السحبيات والخرجيات** | لا يرى إلا ما يخص مصادره |
| **بطاقات ضمار المالك** | **لا يرى بطاقة مصدر خارج نطاقه، ولا تدخل أرقامه في بطاقة «الكل» عنده** |
| حركة النقد · كشف الحساب · حساب الرعوي | مقيَّدة بمصادره |
| مركز الإدخالات المعلّقة | معلّقات مصادره فقط |
| **كل التقارير** | مقيَّدة بمصادره |
| **سجل التدقيق** | أحداث مصادره فقط |

> **`GR-23`:** من حاول قراءة أو كتابة مصدر خارج نطاقه **من خارج التطبيق
> يُرفَض طلبه** — الفلترة في الواجهة **ليست هي الضابط**.

## 5. الصلاحيات التي **لا تُغني عن بعضها**

> **حيث تُشترط صلاحيتان معاً، فالمطلوب اجتماعهما — وغياب أيٍّ منهما ⟵ رفض.**

| العملية | الصلاحيات المطلوبة معاً |
|---|---|
| توزيع مع تسعير فوري | «إضافة توزيعة» **+** «تسعير التوزيع الآن» |
| تعديل سعر ظاهر تلقائياً | «إضافة توزيعة» **+** «تعديل سعر التوزيع» |
| **تصريف متبقٍ متأخر توزيعاً** | «تصريف المتبقي المتأخر» **+** «إضافة توزيعة» |
| **تصريف متبقٍ متأخر بيعاً نقدياً** | «تصريف المتبقي المتأخر» **+** «إضافة بيع نقدي» |
| **إتلاف متبقٍ** | «الإتلاف» ★★ **والسبب اختياري** (`ADR-0020`) |
| بيع نقدي دون الحد الأدنى | «إضافة بيع نقدي» **+** «البيع دون الحد الأدنى» **+ سبب نصي** |
| قبض بتاريخ سابق | «إضافة سند قبض» **+** «قبض بتاريخ سابق» |
| **تأكيد إيداع بنكي** | «عرض حالة الإيداع البنكي» **+** «تأكيد الإيداع البنكي» **+ ملاحظة** |
| **سحبية فيها قات مسعَّر الآن** | «إضافة سحبية» **+** «تسعير القات المسحوب الآن» |
| إدخال ضريبة الجونية لاحقاً | «عرض الجواني» **+** «إدخال الضريبة لاحقاً» |
| **تعديل أي مستند أو حركة معتمدة** | صلاحية التعديل للوحدة ★★ **والسبب اختياري** (`ADR-0020`) |
| **إلغاء أي مستند** | صلاحية الإلغاء للوحدة ★★ **والسبب اختياري** (`ADR-0020`) |
| **أي عملية أعلاه** | **+ أن يكون المصدر ضمن نطاق مصادر المستخدم** |

## 6. صلاحيات العرض المستقلة (تُخفي عناصر بالكامل)

> **هذه ليست صلاحيات كتابة بل صلاحيات رؤية** — ومن لا يملكها **لا يرى
> العنصر إطلاقاً، ولا حتى للقراءة**:

| الصلاحية | ما تُخفيه |
|---|---|
| **«عرض أسعار التوزيع وإجمالياته»** | **عمود السعر والإجمالي كلياً** في التوزيع (`ت-12`) |
| **«عرض حالة الإيداع البنكي»** | **العمود والفلتر** في المقبوضات |
| **«عرض سحبيات المالك»** | **بند السحبيات** في البطاقة وشاشة النقد **وكل التقارير** |
| «عرض الخرجيات» | بند الخرجيات في المواضع نفسها |
| «عرض مالية الجونية» / «عرض مالية الرعوي» | السعر والضريبة والصافي |
| «عرض أرصدة المقاوته» | الأرقام المالية في بطاقة المقوت |
| «عرض بطاقة كل المصادر» | البطاقة التجميعية |
| **«عرض الأثر النهائي على حساب المصدر»** | تقرير `R-23` |

> ⚠️ **كل صلاحية عرض هنا يجب أن يقابلها شرط قراءة فعلي في قواعد الحماية**
> — وإلا فالإخفاء **تجميل واجهة لا حماية**، والبيانات ما زالت قابلة
> للقراءة من خارج التطبيق (`RISK-02`).

## 7. آلية الفرض

```text
عملية من التطبيق
   ↓
المصادقة        →  رمز دخول يحمل: الدور + الصلاحيات + نطاق المصادر
   ↓
حماية العميل     →  رفض أي عميل غير التطبيق الرسمي
   ↓
قواعد الحماية    →  ① الصلاحية التفصيلية
                    ② نطاق المصدر
                    ③ التاريخ والتوقيت
                    ④ عدم سلبية الرصيد
                    ⑤ السبب النصي عند التعديل والإلغاء
   ↓  إن سقط أي فحص → رفض + رسالة عربية + تسجيل
المعاملة الذرّية  →  قراءة الأرصدة وكتابتها ذرّياً
   ↓
العمليات السحابية →  سجل التدقيق · الملخصات · إعادة الاحتساب
```

## 8. جدول التتبّع

**كل صلاحية لها مقابل مكتوب في قواعد الحماية** — الجدول الكامل في
`docs/09-security/security-requirements.md` §3.

> **وأي صلاحية بلا مقابل تُعتبر غير مُنفَّذة أمنياً** مهما منعها كود
> التطبيق (`BR-M1-07` · `RISK-02`).
