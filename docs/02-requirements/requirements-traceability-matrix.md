# مصفوفة تتبّع المتطلبات (RTM) — QTMS

| البند | القيمة |
|---|---|
| **الإلزامية** | **M** — العمود الفقري للتتبّع |
| **الطبيعة** | **LIVING** — تُحدَّث مع كل تغيير في أي طرف من السلسلة |
| **المالك** | محلل الأعمال (BA) · يحدّث Claude Code أعمدة التصميم/الكود/الاختبار |
| **الأساس المعياري** | ISO/IEC/IEEE 29148 · UPDS-04 §2.3 |

---

## 1. كيف تُقرأ هذه المصفوفة

```text
المتطلب  →  التصميم  →  الكود  →  الاختبار
   ↑                                  ↓
   └──────── والعكس صحيح ─────────────┘
```

**قاعدة «لا متطلب يتيم»:** لا يجوز إغلاق أي مرحلة وفيها متطلب بلا **تصميم**
أو بلا **حالة اختبار** دون **تبرير موثَّق** في عمود الملاحظات (UPDS-05 §7).

**دليل الحالة:** `◻️ مخطَّط` · `🔷 مُصمَّم` · `🟩 منفَّذ` · `✅ مُختبَر` ·
`⏸️ محجوب`

> **حالة التنفيذ (2026-08-25):** ✅ **`M1` و`M2` و`M3` و`M4` و`M5` و`M21`
> لها كودٌ فعلي** — `WU-001` و`WU-002` و`WU-026`. ⛔ **وبقية الصفوف ما تزال
> `🔷 مُصمَّم`**، وأعمدةُ كودها فارغة بصدق.
>
> ⚠️ **و`🟩 منفَّذ` هنا تعني «مُنفَّذ برمجياً ومُختبَر آلياً»** ⛔ **لا
> «مُختبَر قبولاً»**: الحالة `✅ مُختبَر` تُمنَح بعد اجتياز `TC-*` و`AT-*`
> المذكورة في عمود الاختبار — ★ **ولا تُمنَح باكتمال الكود وحده.**
